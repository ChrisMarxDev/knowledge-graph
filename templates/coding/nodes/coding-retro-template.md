# Retrospective guide

Use this guide to examine a specific session, diff, pull request, incident, or
milestone. It contains questions, not findings about this project.

## What changed our understanding? {#learning}

Which expectation was contradicted? Which constraint was discovered? What
approach was rejected, including changes abandoned before a diff existed?
What evidence supports each conclusion?

## What belongs in the collection? {#capture}

Read related nodes first. Update existing knowledge when it represents the same
subject. Use the collection's types for durable findings; a retro is a workflow,
not a mandatory node type. Skip routine progress reports and facts already clear
from code. Record unknowns as questions rather than invented rationale.

## What should be reconsidered? {#follow-up}

Identify existing conclusions whose assumptions changed, and concrete conditions
for a later review. Preserve historical reasoning. Report unresolved
contradictions and what the retrospective did not cover.
