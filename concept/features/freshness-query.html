03 · Freshness: authored checkpoint

Add one optional top-level review field. Keep it in the node so review state survives Git, copying, and cache deletion. This is an assertion by the caller that the current knowledge has been reviewed; the CLI cannot verify the review occurred. A timestamp alone never means “true”. 

# Existing node frontmatter; unrelated fields are omitted here.
id: refund-idempotency
sources:
  - kind: file
    target: docs/refunds.md
    locator: Retry behavior
  - kind: reference
    target: Maintainer decision, 2026-10-01
review:
  version: 1
  reviewedAt: "2026-10-19T10:00:00.000Z"
  dueAt: "2027-01-17T10:00:00.000Z"  # optional
  nodeDigest: "sha256:<64 lowercase hex characters>"
  sourceDigests:
    - kind: file
      target: docs/refunds.md
      locator: Retry behavior
      digest: "sha256:<64 lowercase hex characters>"
Field / rule Exact semantics
version Integer 1. Unknown version/keys, invalid dates, duplicate source identities, or malformed digests are diagnostic errors.
nodeDigest SHA-256 of UTF-8 canonical JSON: {version:1, frontmatter:parsed data excluding review, body:body with CRLF normalized to LF}. Recursively sort object keys; preserve array order and strings. Reject cyclic/non-JSON-compatible values for review. YAML comments/key order do not invalidate; prose/metadata/links/source edits do.
sourceDigests One entry per unique file-kind source identity (kind,target,locator; missing locator differs from a value). Sort identities lexically for deterministic output. Fingerprint raw file bytes, not mtime.
Scope Hash file-kind sources only. files associations are not evidence. URLs/reference citations are uncheckable automatically. No HTTP fetches. locator stays descriptive; hash the whole file even for a section citation.
No evidence files A node can still have a review age and nodeDigest. Zero tracked sources is explicit coverage, not proof that outside circumstances did not change.
dueAt Optional expiry. --due-in N adds N×86400 seconds to reviewedAt; integer 1–3650. Omission preserves the previous review interval when present, otherwise no deadline. No arbitrary collection-wide expiry default.
Existing arbitrary review field Inventory before implementation/migration. Incompatible existing fields are reported; never overwritten automatically. No forced migration of existing nodes.

04 · Freshness result: separate observations

type FreshnessResult = {
  id: string;
  path: string;
  checkpoint: "absent" | "valid" | "invalid";
  node: "unchanged" | "changed" | "untracked" | "unknown";
  age: "not-due" | "overdue" | "no-deadline" | "unreviewed" | "unknown";
  sources: Array<{
    kind: "file" | "url" | "reference";
    target: string;
    locator?: string;
    state: "unchanged" | "changed" | "untracked" | "missing"
         | "unreadable" | "unsafe" | "unstable" | "uncheckable";
    expectedDigest?: string;
    actualDigest?: string;
  }>;
  coverage: { trackedFiles: number; untrackedFiles: number; uncheckableSources: number };
  needsReview: boolean;
  reasons: string[];
  reviewToken: string | null;
};
Case Result
No checkpoint checkpoint=absent; node=untracked; age=unreviewed; needsReview=true
Node edited; evidence unchanged node=changed; reasons includes NODE_CHANGED
Cited file edited source.state=changed; reasons includes SOURCE_CHANGED
Now ≥ dueAt age=overdue; reasons includes REVIEW_OVERDUE
No files; reference citation only; reviewed; no deadline node=unchanged; age=no-deadline; coverage={trackedFiles:0,untrackedFiles:0,uncheckableSources:1}; needsReview=false, but no external change coverage
File missing/unreadable/unsafe/changes during hash Corresponding source state; needsReview=true; reviewToken=null
Added/removed source identity Node digest changes; new source is untracked; removed baseline entry is reported via SOURCE_SET_CHANGED
Invalid review or malformed node/source metadata checkpoint=invalid or per-node diagnostic; needsReview=true; no token; repair explicitly
Uncheckable URL/reference Reported in coverage. Does not alone cause needsReview once reviewed; expiry remains the only automatic temporal trigger.

needsReview is true for absent/invalid checkpoint, changed node, overdue age, changed/untracked/unavailable file source, or source-set mismatch. It is not a truth classifier. All file sources are still checked when the checkpoint is absent, so the first review token binds to actual evidence.

05 · Freshness CLI and write concurrency

# Read-only, with a paged result envelope.
kw --json freshness refund-idempotency
kw --json freshness --state needs-review --limit 20 --offset 0

# After reading/rechecking the node and its evidence:
kw --json review refund-idempotency \
  --expect sha256:REVIEW_TOKEN_FROM_FRESHNESS --due-in 90 --dry-run
kw --json review refund-idempotency \
  --expect sha256:REVIEW_TOKEN_FROM_FRESHNESS --due-in 90

# Query can combine the same computed predicate with existing filters.
kw --json query --freshness needs-review --fields id,title
Contract Definition
freshness flags --state any|needs-review|unchanged|unreviewed (any); --limit 20; --offset 0. “unchanged” means valid checkpoint AND needsReview=false; not verified truth. “unreviewed” means checkpoint absent. ID uses the existing unique node/path resolver, not section IDs.
Envelope {ok:true,results:FreshnessResult[],total,nextOffset,warnings}. Filter then page; path order. total covers matched parsed nodes; parse failures are always in warnings. With ID, unknown/ambiguous ID is an operational error.
Exit codes freshness: 0 if no review findings; 1 if any selected result needsReview or collection parse warnings prevent a complete check, even beyond the returned page; 2 for invalid invocation/project failure. Query remains exit 0 for successful discovery, including needs-review results.
Token SHA-256 over canonical {version:1,node raw-byte digest,current unique file source identities+digests}. A token is optimistic concurrency, not authentication. Age is excluded. No token when any required input is invalid/unavailable.
Review write Acquire existing node lock; recompute and compare token; prepare checkpoint; recheck evidence and node before atomic replacement. Mismatch: exit 2, no node write. --dry-run still validates and returns planned edit.
Review output Existing edit envelope: {ok:true,path,before,after,applied}. No automatic commit, body changes, or source edits. No bulk review command.
Filesystem limit Use project-boundary and regular-file checks, bounded streaming, and before/after stat checks. Cache each source digest once within a command. Concurrent source writes can still occur after the last check: no cross-file transaction is claimed; a later check detects the change.
Self evidence Reject a checkpoint if a cited file resolves to the node itself: writing review changes the cited file and creates an immediate self-invalidating baseline.
Errors Keep current error.code=COMMAND_FAILED and exit 2. Add optional error.reason for machine handling: REVIEW_INPUT_CHANGED, INVALID_REVIEW, SOURCE_UNAVAILABLE. Existing consumers retain code/message.

06 · Query v1: explicit alternative terms

Recommended before embeddings. The caller supplies alternates; no hidden expansion. Without new options, preserve the existing single-query ranking, output shape, limits, and defaults. 

# Existing behavior:
kw --json query "prevent duplicate payments" --fields id,title

# Proposed: union of three independently executed lexical queries.
kw --json query "prevent duplicate payments" \
  --also-text "idempotency" \
  --also-text "retry" \
  --type rule --fields id,title --explain

# This works even if every matching node has links: [].
queries = stableUnique([text, ...alsoText]);  // trim, preserve case
eligible = existingMetadataViewAndFileFilters(scan());
if (freshnessFilter) eligible = filterByFreshness(eligible);

lists = queries.map(q => lexicalSearchAllCurrentRoots(q));
for each list:
  map hits to eligible node paths;
  drop stale/unmapped hits; deduplicate by node path;
  preserve QMD score order; break score ties by relative path;
  assign rank starting at 1 AFTER eligibility filtering;

if (queries.length === 1): use the existing QMD ordering;
else:
  score(node) = SUM over matching lists (1 / (60 + rank(node, list)));
  union lists; sort by score descending, then relative path ascending;

page AFTER union + ranking; project cards exactly as today;
if (explain): add explanations for returned results only;
Parameter Semantics
--also-text TEXT Repeatable. Requires nonempty positional text. Up to 8 distinct total queries, each 1–500 characters when using expansion; exact trimmed duplicates collapse. Each phrase is independently interpreted by the existing lexical backend. No promise of literal phrase matching.
--explain Adds top-level retrieval and explanations fields. Results remain cards/projections, including --fields title returning title only. No implicit id/path in projected cards. Metadata-only query is supported with no lexical contributions.
--freshness STATE any|needs-review|unchanged|unreviewed; any is default and performs no hashing. Uses exactly the freshness predicate. Filters before keyword ranks/pagination. Freshness never silently lowers a relevance score.
Ranks/scores RRF constant 60; equal weight per distinct query. Missing list contributes zero. Relevance scores are ordering signals, not probabilities/confidence. Repeated terms cannot boost a result by duplicate queries.
Zero results Successful empty results and total=0. No fabricated links, fallback query, automatic source search, or automatic semantic fallback.
Identity Deduplicate by node path as current CLI; duplicate IDs remain diagnosed, never merged. All modes use current configured roots.
Pagination total = exact union count of eligible lexical hits returned by existing all-results keyword adapter. nextOffset behaves as today. No cross-invocation snapshot: edits can reorder later pages, as today.
Cost Open one QMD store; update once; run ≤8 lexical searches; close once. Avoid the current helper’s per-call update cost. No model inference or downloads.

Choose the snippet from the contributing query with the lowest rank; ties use query order. Use existing QMD snippet extraction, capped at 500 characters. Null if unavailable. 1. Agent issues the user's question as a normal query.
2. Inspect returned snippets / known project vocabulary when needed.
3. Agent explicitly supplies alternate terms with --also-text.
4. Inspect --explain; read selected node IDs for full context.
5. Use link show only when authored relationships help the task.

09 · Semantic search: conditional alternative

Not a required dependency of query v1. The installed QMD 2.8.3 SDK exposes embed() and searchVector(); its generic search() also introduces expansion/reranking. Do not call the generic pipeline by accident. 

# CONDITIONAL API, only if evaluation justifies this phase:
KW_EMBED_MODEL=/absolute/path/to/local-model.gguf kw index --semantic
KW_EMBED_MODEL=/absolute/path/to/local-model.gguf \
  kw --json query "avoid charging twice" --mode hybrid --explain

# --mode keyword|semantic|hybrid; default remains keyword.
# --candidates 200 (range 20–2000); semantic/hybrid only.
# --also-text is initially keyword-only; incompatible combinations fail.
Issue Proposed constraint / implementation gate
Input Embed node title + description + Markdown body only. Never fetch/parse cited source contents, links as relationships, or review digests into semantic text.
Storage Derived documents under .knowledge/cache/semantic/documents/, separate QMD DB and manifest. Path keys are SHA-256 of project-relative node path; manifest maps to actual node path/ID. No new authored source of truth.
Model Explicit existing local file via KW_EMBED_MODEL; fingerprint actual bytes. No automatic model download. Model choice and redistribution are unresolved. Model errors must not silently become empty results.
Index lifecycle index --semantic refreshes generated docs, removes deleted/out-of-scope entries, updates QMD, embeds changed content, and atomically publishes a manifest under a cooperating cache lock. Interrupted build remains unready.
Stale index Query compares content/model/root manifest. Missing/mismatched index fails exit 2 with reason SEMANTIC_INDEX_MISSING or SEMANTIC_INDEX_STALE and a suggested rebuild. No query-time document embedding; query embedding is expected.
Filtered recall SDK vector retrieval selects candidates before kw metadata filtering; it cannot enforce arbitrary eligible node IDs through its public API. Increasing limit is not proof of exhaustiveness. Return retrieval.exhaustive=false, candidateLimit, and totalScope="retrieved-candidates". A filtered empty result is not proof the corpus lacks a match.
Hybrid Fuse lexical and semantic candidate ranks with documented RRF; exact metadata/view/file/freshness filters still apply before output pagination. total counts the resulting candidate union, not all semantically relevant nodes.
Hard gate If users require exhaustive filtered vector ranking, stop and design a supported eligible-ID retrieval adapter/upstream API. Do not access undocumented QMD database internals to disguise the limitation.
Cost / dependencies Measure model memory, cold/warm latency, disk growth, install feasibility, dependency advisories, and actual retrieval gains before adoption. Serialize SDK store work because its configuration source is process-global.

10 · Optional explorer HTTP delta

CLI first. This is an explicit follow-up, not an implicit replacement of existing /api/search or graph snapshot shapes. 

GET /api/query?q=prevent%20duplicate%20payments
    &alsoText=idempotency&alsoText=retry
    &view=backend&type=rule&file=src/payments.ts
    &fields=id,title&explain=true&freshness=needs-review&limit=20&offset=0

GET /api/freshness?id=refund-idempotency
GET /api/freshness?state=needs-review&limit=20&offset=0

Both routes call the same service functions as CLI. GET /api/query maps q→text, repeated alsoText/file→arrays, view/type/fields/filter→existing query meanings, repeated dimension=name=value→AND predicates. Defaults match CLI. Invalid limits/enums/JSON/booleans/unknown query keys return HTTP 400. Unknown/ambiguous IDs follow the existing HTTP 400 convention. Freshness findings return HTTP 200 with data, never HTTP failure. Response envelope matches CLI including ok. Keep GET-only localhost/origin restrictions. No HTTP review mutation. Do not compute freshness across every node on graph polling; request it for a selected node or an explicit review list.

Open decision Proposed default
Approve explicit alternatives as first query improvement? Yes; directly borrows the workflow benefit without claiming automatic semantic matching.
Should expiry be mandatory for knowledge with no checkable sources? No; make coverage visible and let caller set --due-in. Mandatory expiry would impose a workflow policy.
Whole-file source noise acceptable? Start whole-file. Structured section selectors need a separate source-locator contract; existing locator text cannot be interpreted safely.
